## Phase 7: 收尾打磨

### Task 7.1: 清理与文案检查

**决策**：单机中文小工具不做国际化，文案直接硬编码在代码里，**不建 strings.xml**（初版建了 strings.xml 但代码无一处引用，是死资源）。

- [ ] **Step 1: 文案规范检查**

全局检索 UI 文案，以下词汇出现次数必须为 0（设计系统第八节文案规范）：

```bash
grep -rn "错误\|失败\|必须" app/src/main/java/ --include="*.kt" | grep -v "未能\|没能"
```

允许的例外：`没能…`、`出了点问题` 这类温和表述。

- [ ] **Step 2: 死代码/未用 import 检查**

```bash
./gradlew lintDebug
```

重点看：unused import、dead code 警告，顺手清掉。

- [ ] **Step 3: Commit**

```bash
git add -A && git commit -m "chore: copy polish and lint cleanup"
```

### Task 7.2: 最终检查清单（并入规格书验收清单）

**构建与运行**
- [ ] `./gradlew assembleDebug` 编译通过
- [ ] 安装到真机/模拟器，冷启动 < 2 秒
- [ ] Manifest 只有 `READ_SMS` 一个权限，无 `INTERNET`

**规格书验收清单（spec 十四，逐条过）**
- [ ] 1. 首次启动 → 权限引导（含合规声明）→ 授权 → 进入主页面
- [ ] 2. 快递列表 → 卡片按天分组（标题格式「今天 · 5月30日」）→ 已取件置灰+删除线 → 分组可折叠
- [ ] 3. 卡片交互 → 展开详情（左侧强调色细线）→ 复制各字段（单号/取件码/地址/电话）→ 勾选圆圈标记已取件（空心描边 ↔ 实心白勾）
- [ ] 4. 快捷操作 → 全部已取（二次确认，无未取时置灰） → 按天已取（二次确认，该天无未取时按钮隐藏）
- [ ] 5. 匹配规则列表 → 预置规则可见（浅灰「预置」标签）→ 新增/编辑/删除（二次确认）/分享规则
- [ ] 6. 规则编辑器 → 粘贴短信 → 分词展示（**分词区吸顶不滚走**）→ 点击填入锚点（选中态主色填充）→ 底部与列表页完全一致的卡片实时预览 → 底部固定保存大按钮
- [ ] 7. AI 辅助 → 粘贴短信 → 生成提示词 → 复制 → 粘贴 AI 返回（含 ```json 围栏也能解析）→ 自动跳转编辑器回显
- [ ] 8. 规则导入/导出 → 全量导出 JSON → 单条导出分享 → 导入 JSON 文件（同名逐条 覆盖/跳过 → 结果摘要）
- [ ] 9. 性能 → 全量扫描无卡顿 → 列表滚动无掉帧
- [ ] 10. 稳定性 → 异常短信不崩溃 → 存储满等异常温和 Toast → 空状态有引导
- [ ] 11. 合规 → 权限引导页 + 设置页均有本地存储声明

**编辑规则后的重扫**
- [ ] 编辑已有规则保存 → 弹「要用新规则重新扫描之前没匹配到的短信吗？」→ 确认后回列表页自动重扫

**权限边界（edge-cases 一）**
- [ ] 拒绝权限 → 空状态 + 前往授权按钮可用
- [ ] 永久拒绝 → 跳本应用系统设置页
- [ ] 使用中权限被回收 → 已有数据可查看 + 顶部 banner 提示
- [ ] 空收件箱 → 显示「还没有快递消息」，不误报无权限

**数据正确性**
- [ ] 删光全部规则（含预置）→ 重启 App 预置规则不复活
- [ ] 同日同单号同取件码 → 不重复入库
- [ ] 同日同单号不同取件码（换柜）→ 覆盖旧记录
- [ ] 编辑预置规则保存后仍是预置标签、创建时间不变
- [ ] UTC+8 时区下「按天已取」标记的天与界面分组一致
