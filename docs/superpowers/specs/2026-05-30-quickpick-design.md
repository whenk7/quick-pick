# 取件宝 (QuickPick) — 产品设计规格书

## 概述

- **项目名**：取件宝 (QuickPick)
- **定位**：精致流畅的 Android 快递取件信息管理应用。通过短信读取自动提取快递信息，集中展示取件码/柜号、单号、地址等内容。支持自定义匹配规则和 AI 辅助生成规则。
- **目标用户**：经常收到快递短信的 Android 用户。
- **核心场景**：打开应用 → 快递取件信息按天整理好 → 取件码一目了然 → 取完一键标记。

## 不做的事

- 物流实时追踪（不接入快递 API）
- 云端同步或账号系统
- 跨平台（仅 Android）
- 广告或任何形式的数据收集
- AI 直调 API（仅支持复制提示词模式）

| 匹配规则 | 管理预置与自定义提取规则 |
| 设置 | 导入导出、快捷操作、关于 |

## 二、快递列表

### 提取字段

每条快递短信提取以下字段：

| 字段 | 说明 |
|------|------|
| 快递公司名 | 规则名称，即快递公司名 |
| 快递单号 | 运单编号 |
| 取件码 | 统一字段：取件码 / 快递柜号 / 货架号 |
| 取件地址 | 统一字段：驿站名 / 取件地址 |
| 快递员电话 | 可选，短信中有则显示，无则隐藏 |
| 接收时间 | 短信接收时间戳 |

### 卡片状态

- **未取件**：正常展示，取件码用强调色大字突出
- **已取件**：置灰变淡（降透明度），保留在列表中不删除
- **不完整**：字段提取不全的标注"不完整"，引导用户优化规则

### 卡片交互

- 轻点 → 展开/收起详情，展开态左侧出现强调色细线
- 点击单号/取件码/地址/电话 → 复制到剪贴板，Toast 提示
- 勾选圆圈 → 标记为已取件

### 快捷操作

- **一键全部已取件**：需要二次弹窗确认
- **按天一键已取件**：每个日期分组内有独立按钮，同样需要二次确认

### 按天分组

快递卡片按接收日期分组，分组可折叠。标题格式：`今天 · 5月30日` / `昨天 · 5月29日` / `5月27日 · 周二`。

## 三、短信解析流程

### 匹配引擎

- 使用**前缀/后缀锚点**定位，纯字符串 `indexOf` 匹配，不使用正则
- 找到 `prefix` → 取其后内容 → 直到 `suffix` 截止
- 字段全部可选，未配置前后缀的字段不参与匹配

### 首次启动

1. 用户授权短信权限
2. 全量扫描系统短信
3. 逐条短信依次跑所有匹配规则
4. 多规则同时命中时：优先取匹配字段数最多的；字段数相同时按规则列表顺序（预置在前）
5. 提取成功 → 生成快递卡片存入本地 Room 数据库
6. 未匹配短信 → 记录已扫过，不再重复

### 增量处理

- 新短信到达 → 仅对新短信跑规则
- 用户手动刷新 → 全量重扫
- 用户新增/修改规则 → 可手动点击重新扫描，仅对之前未匹配的短信重试

### 性能

- 1000 条短信 × 20 条规则，纯字符串匹配，毫秒级完成
- 瓶颈在读取短信数据库（IO），不在匹配计算

### 去重与范围

- 同一日期 + 同一单号 → 仅保留一条
- **仅关注取件短信**（含取件码/柜号/地址），纯物流状态通知（"您的快递正在派送"等）不处理
- 用户删除系统短信 → 不影响 app 内已提取的记录（独立存储）

## 四、匹配规则

### 规则 JSON 格式

```json
{
  "name": "顺丰速运",
  "fields": {
    "trackingNumber": { "prefix": "单号", "suffix": "，" },
    "pickupCode":    { "prefix": "取件码：", "suffix": "。" },
    "address":       { "prefix": "到达", "suffix": "，" },
    "phone":         { "prefix": "电话：", "suffix": " " }
  }
}
```

- `name`：规则名称 = 快递公司名，支持修改
- `fields`：每个字段由前缀 + 后缀两个锚点定义，字段全部可选
- 无正则，无优先级数值，无额外元数据

### 规则列表

- 预置规则与自定义规则分两组展示
- 每条显示：公司名、已配置字段数、预置/自定义标签、单条分享按钮
- 支持：新增、编辑、删除、单条导出分享

### 预置规则

预置常见快递公司模板（顺丰、京东、极兔、中通、圆通、韵达、申通、邮政 EMS），基于公开常见短信格式预设。用户可修改或删除。

## 五、匹配规则编辑器

### 整体流程

1. 用户从系统短信 App 复制一条原始短信文本
2. 回到取件宝，粘贴到规则编辑器的短信输入区
3. 短信文本原地变为**可点击分词块**（类似文本大爆炸），分词区吸顶悬浮
4. 下方列出所有可提取字段的卡片，每张卡片包含前缀输入框 + 后缀输入框
5. 用户点击分词块 → 自动填入当前选中字段的前缀/后缀框；也可手动输入
6. 实时预览：底部显示匹配结果渲染成的**快递卡片**（与列表页卡片样式一致）
7. 保存，规则名称默认为从短信中匹配到的公司名

### 交互细节

- 每个字段卡片有一个独立主题色点（取自快递公司色标）
- 点击某字段卡片 → 选中态：卡片抬高阴影 + 左侧出现强调色线 + 微右移
- 再点击分词块 → 前后文本自动识别填入锚点框
- 已配置字段卡片：左侧绿线 + 已配置标签
- 空字段卡片：半透明
- 分词块：无色表示普通、绿色边框表示已有规则匹配、选中态用强调色填充

### 预览

底部展示一条与列表页样式完全一致的快递卡片，实时反映当前锚点配置的匹配结果。匹配到的内容正常显示，未匹配字段显示灰色占位。用户可直观判断规则是否正确。

## 六、AI 辅助生成规则

仅支持提示词模式（不内置 API 调用）：

1. 用户粘贴一条原始短信到 AI 功能页
2. App 将短信内容嵌入预置提示词模板，生成完整 prompt
3. 用户一键复制 prompt → 去任意 AI 服务粘贴提问
4. AI 返回 JSON → 用户复制 JSON
5. 回到取件宝 → 点"导入 AI 结果" → 粘贴 JSON
6. 自动跳转到规则编辑页，JSON 回显为 UI 表单
7. 用户检查修正后保存

预置提示词为中文，指导 AI 分析短信文本、为每个字段识别前后缀锚点，输出规范 JSON。

---

## 七、规则导入/导出

- **全量导出**：设置页 → "导出全部规则" → 一个 JSON 文件包含所有规则 → 分享/保存
- **单条导出**：规则列表中每条规则有分享按钮 → 导出单个规则 JSON 文件
- **导入**：设置页 → "导入规则" → 选择 JSON 文件 → 同名规则提示"覆盖 / 跳过" → 无同名则新增 → 在规则编辑器中回显确认

---

## 八、设置页

- 快捷操作：一键全部已取件、一键按天已取件
- 规则管理：导入规则 / 导出全部规则
- 关于：版本号、项目链接
- 合规声明：醒目标注"所有数据仅存储在本地，不上传、不联网、不收集任何用户信息"

## 九、首次启动与权限引导

首次打开应用展示引导页：
1. 说明为什么需要短信权限
2. 醒目标注合规声明
3. "授权短信权限"按钮 → 触发系统权限弹窗
4. 授权成功进入主页面

---

## 十、数据存储与合规

- 所有数据存储在设备本地数据库（Room）
- 不包含任何网络请求代码
- 不包含任何第三方 SDK
- 权限引导页和设置页底部均标注："所有数据仅存储在本地，不上传、不联网、不收集任何隐私信息"
- 卸载 → 所有数据清除

---

## 十一、非功能性需求

### 性能
- 全量短信匹配：毫秒级
- 列表滚动：跟随设备刷新率（90Hz / 120Hz / 144Hz），无掉帧
- 冷启动时间：< 2 秒

### 稳定性
- 格式异常的短信不崩溃，优雅跳过
- 规则部分字段匹配失败 → 卡片标注"不完整"
- 空状态有友好引导

### 合规
- 权限引导页 + 设置页双处标注"本地存储、不上传、不联网"

---

## 十二、技术选型

- **语言**：Kotlin
- **UI 框架**：Jetpack Compose + Material 3
- **本地数据库**：Room
- **最低 API**：30（Android 11）
- **架构**：MVVM
- **匹配引擎**：纯字符串锚点匹配
