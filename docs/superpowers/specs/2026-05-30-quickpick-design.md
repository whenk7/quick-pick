# 取件宝 (QuickPick) — 产品设计规格书

## 概述

- **项目名**：取件宝 (QuickPick)
- **定位**：一款精致流畅的 Android 快递取件信息管理应用。通过短信自动提取快递信息，集中展示取件码/柜号、单号、地址等内容，支持自定义匹配规则和 AI 辅助生成规则。
- **目标用户**：经常收到快递短信的 Android 用户。
- **核心场景**：用户打开应用，快递取件信息已经按天整理好，一目了然；取完件后一键标记，干净利落。

## 不做的事

- 物流实时追踪（不接入快递 API）
- 云端同步或账号系统
- 跨平台（仅 Android）
- 广告或数据收集

---

## 一、App 结构

底部导航栏三个 Tab：

1. **快递列表** — 主页面，所有提取出的快递卡片，按天分组展示
2. **匹配规则** — 管理预置与自定义的提取规则
3. **设置** — 导入导出、快捷操作、关于

---

## 二、快递列表

### 卡片内容

每条提取出的快递显示为一张卡片，包含以下字段：

| 字段 | 说明 |
|------|------|
| 快递公司名 | 匹配规则名称，即为快递公司名 |
| 快递单号 | 运单编号 |
| 取件码 | 统一字段：取件码 / 快递柜号 / 货架号 |
| 取件地址 | 统一字段：驿站名称 / 取件地址 |
| 快递员电话 | 可选字段，短信中有则显示，无则隐藏 |
| 接收时间 | 短信接收时间戳 |

### 卡片状态

- **未取件**：正常卡片样式，醒目展示
- **已取件**：用户手动标记后置灰变淡，但不从列表移除
- **不完整**：字段提取不全的标注"不完整"，提醒用户优化规则

### 卡片交互

- 轻点卡片 → 展开/收起详情
- 长按或点击复制按钮 → 复制对应字段（单号、取件码、地址等），Toast 提示
- 右上角勾选 → 标记为已取件

### 快捷操作

列表顶部提供两个操作按钮：
- **一键全部已取件**：将当前所有未取件记录标记为已取件
- **按天一键已取件**：每个日期分组内有独立按钮，仅标记当天分组内的未取件

### 按天分组

快递卡片按接收日期分组，每个分组可折叠/展开。分组标题格式：`今天` / `昨天` / `2026年5月28日`。

## 三、短信解析流程

### 首次启动

1. 用户授予短信读取权限
2. App 全量扫描系统短信收件箱
3. 逐条短信跑所有匹配规则
4. 提取成功 → 生成快递卡片存入本地数据库
5. 未匹配短信 → 记录"已扫过"，不再重复尝试

### 后续增量

- 系统收到新短信 → 仅对新短信跑规则（增量处理）
- 用户新增/修改规则后 → 可手动点击"用新规则重新扫描"，对之前未匹配的短信重试

### 用户手动刷新

- 下拉刷新 → 全量扫描
- 1000 条短信 × 20 条规则 → 纯字符串匹配（非正则），毫秒级完成

### 去重

- 同一日期 + 同一单号 + 同一规则匹配 → 仅保留一条
- 仅关注取件短信（有取件码/柜号/地址的），纯物流通知不处理

### 与系统短信的关系

- 用户删除系统短信 → 不影响 app 内已提取的快递记录（独立存储）
- App 仅读取短信，不修改、不删除任何系统短信

## 四、匹配规则

### 规则模型

每条匹配规则存储为 JSON，结构如下：

```json
{
  "name": "顺丰速运",
  "fields": {
    "trackingNumber": { "prefix": "单号", "suffix": "，" },
    "pickupCode":    { "prefix": "取件码：", "suffix": "。" },
    "address":       { "prefix": "地址：", "suffix": "。" },
    "phone":         { "prefix": "电话：", "suffix": " " }
  }
}
```

- `name`：规则名称，即快递公司名，支持修改
- `fields`：各提取字段，每个字段由前缀锚点 + 后缀锚点定义
- 提取逻辑：在短信原文中找到 `prefix`，取其后内容，直到 `suffix` 截止
- 字段全部可选（用户按实际短信情况选填）
- 匹配引擎不使用正则，纯字符串 `indexOf` 定位，保证速度

### 规则列表

- 预置规则置顶，自定义规则排下方
- 每条显示：公司名（规则名称）、匹配字段数
- 支持：新增、编辑、删除、单条导出、单条分享

### 预置模板

预置常见快递公司的匹配规则（顺丰、京东、极兔、中通、圆通、韵达、申通、邮政 EMS），基于公开常见短信格式预设。用户可根据自己收到的短信修改或删除。

---

## 五、匹配规则编辑器（核心功能）

### 整体流程

1. 用户从系统短信 app 复制一条原始短信文本
2. 回到取件宝，粘贴到规则编辑器的短信输入框
3. 短信文本自动分词拆块（类似文本大爆炸效果），每个分词可点击
4. 下方列出所有可提取字段（公司名、单号、取件码、地址、电话），每个字段有一个前缀输入框和一个后缀输入框
5. 用户点击分词块 → 自动填入当前选中字段的前缀/后缀框；也可以直接手动输入
6. 实时预览：短信原文中已匹配的内容高亮显示
7. 所有字段设好后保存，规则名称默认为公司名对应的字段提取值，支持修改

### 操作细节

- 点击某字段行 → 选中该字段（高亮）
- 再点击短信分词块 → 自动识别该词在短信中的前后文本，分别填入前缀框和后缀框
- 所有输入框可手敲编辑
- 预览区实时反映匹配结果：绿色高亮 = 匹配成功，红色高亮 = 锚点找到但内容异常
- 输入框为空 → 不匹配该字段（允许字段不完整）

### 匹配优先级

多条规则同时匹配同一条短信时：
1. 优先采用匹配字段数更多的规则
2. 字段数相同时，按规则在列表中的顺序（预置优先）

## 六、AI 辅助生成规则

### 仅支持模式 B（复制提示词）

流程：
1. 用户在 AI 功能页粘贴一条原始短信内容
2. App 将短信内容嵌入预置提示词模板，生成完整 prompt
3. 用户一键复制 prompt → 去任意 AI 网站/App 粘贴提问
4. AI 返回规则 JSON → 用户复制 JSON
5. 回到取件宝 → 点"导入 AI 结果" → 粘贴或加载 JSON
6. 自动跳转到规则编辑页，JSON 内容回显为 UI 表单
7. 用户检查、修正、实时预览 → 确认无误后保存

### 预置提示词

提示词为中文，指导 AI 分析短信文本、识别快递字段的前后缀锚点，输出规范 JSON 格式。

---

## 七、规则导入/导出

- **全量导出**：设置页 → "导出全部规则" → 生成一个包含所有规则的 JSON 文件 → 分享或保存
- **单条导出**：规则列表 → 点击单条规则的分享按钮 → 导出单个规则 JSON → 分享
- **单条导入**：设置页 → "导入规则" → 选择 JSON 文件 → 解析成功 → 同名规则提示"覆盖/跳过"，无同名则新增 → 回显在规则编辑器供确认

---

## 八、设置页

- **快捷操作入口**：一键全部已取件、一键按天已取件（与列表页快捷按钮功能一致）
- **规则管理**：导入规则 / 导出全部规则
- **关于**：版本号、项目链接
- **合规声明**：明确标注"所有数据仅存储在本地，不上传、不联网、不收集任何用户信息"

---

## 九、首次启动与权限引导

### 权限引导页

首次打开应用时展示一个引导页面，内容：
1. 说明为什么需要短信权限（识别快递短信、提取取件信息）
2. 明确声明：所有数据仅存储在设备本地，不上传、不联网、不收集任何隐私信息
3. 一个"授权短信权限"按钮 → 触发系统权限弹窗
4. 授权成功后进入主页面

---

## 十、数据存储

- 所有数据存储在设备本地数据库（Room），包括：
  - 已提取的快递记录
  - 匹配规则（预置 + 自定义）
  - 已扫描过的短信 ID（用于去重和跳过）
- 不接入任何网络服务
- 不包含任何第三方数据收集 SDK
- 用户卸载应用 → 所有数据随之清除

---

## 十一、非功能性需求

### 性能
- 全量短信扫描：1000 条短信毫秒级完成匹配计算
- 列表滚动：60fps 流畅，无掉帧
- 冷启动时间：< 2 秒
- 内存中操作，无 IO 瓶颈

### 稳定性
- 格式异常的短信不崩溃，优雅跳过
- 规则匹配失败时降级展示（标注不完整）
- 空文件夹状态有友好引导

### 合规
- 首次启动和设置页均醒目标注"所有数据仅存储在本地"
- 不联网、不上传、不收集
- 短信权限仅用于读取快递相关短信

---

## 十二、技术选型

- **语言**：Kotlin
- **UI 框架**：Jetpack Compose + Material 3
- **本地数据库**：Room
- **最低 API**：30（Android 11）
- **架构**：MVVM
- **匹配引擎**：纯字符串锚点匹配（非正则）
