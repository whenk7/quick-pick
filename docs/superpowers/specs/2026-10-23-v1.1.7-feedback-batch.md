# v1.1.7 反馈批次 + 沉浸式取件模式 设计

日期：2026-10-23
状态：已讨论定稿（用户逐条拍板，见各节「裁决」）
前置版本：v1.1.6（main @ ac9bbdc）

## 背景

v1.1.4–v1.1.6 三连版真机验收后，用户集中反馈 11 条问题；另加一个新功能「沉浸式取件模式」。经 brainstorming 逐条对齐，本 spec 是最终裁决的完整记录。

用户明确拍板的四个关键选择：
1. 卡片手势：单击=无，长按=短信原文弹窗，左滑=已取件，右滑=无
2. Snackbar 合并：新消息顶掉旧的（同条换文案），不排队
3. 主题：砍掉「固定/动态」引擎概念，统一为动态取色开关+种子色网格
4. 地址别名：全局地址簿（不挂规则）

用户明确的否定项（不做）：
- 卡片上任何复制功能（单击复制、长按复制、复制文字按钮全删）
- 原文弹窗不加「复制提取信息」按钮（维持只有「复制全文」）
- 已取件卡不加左滑取消（取消走圆圈）
- 右滑不做任何动作
- 导入判重维持按规则名称，不改

## 一、Bug 修复

### 1.1 删光规则后重扫不清记录

**根因**：`PackageListViewModel.scanSms()` 中 `if (rules.isEmpty()) return@launch` 提前返回，`removeUnmatched` 清理逻辑在后续循环里永远执行不到。

**修法**：
- `PackageRecordDao` 新增 `deleteAllUnpicked()`（`DELETE WHERE is_picked_up = 0`）
- `scanSms`：规则为空时——`removeUnmatched=true`（手动下拉）→ 调 `deleteAllUnpicked()`；`removeUnmatched=false`（增量）→ 维持提前返回不动存量
- 已取件历史任何情况都保留

**测试**：`PackageRepositoryTest` FakeDao 加用例（空规则重扫→未取件清空、已取件不动、增量扫描不动存量）。

### 1.2 编辑器预览消失（先复现再修）

**已知假设**：老规则无 `sampleSms` → 打开编辑器短信区为空 → `preview=null` → 无预览卡。代码链路（`refreshPreview` 各触发点、`preview != null` 渲染条件）审查未见缺陷。

**步骤**：先用 Robolectric 渲染编辑器各状态（新建无短信 / 新建有短信 / 编辑有样例规则）复现；若实锤为无样例场景，修法 = 空短信区占位文案补引导「粘贴一条快递短信，下方实时预览」。若复现为其他根因，回报后再定修法。

## 二、弹窗与返回语义统一

**目标语义**（用户原话裁决）：
- 有取消能力的弹窗：系统返回 = 原地关闭弹窗，禁止跳转到别处
- 强制裁决弹窗（导入同名冲突、AI 页冲突）：系统返回 = 无效；点弹窗外部也不关——必须点按钮
- 双击退出只在「快递/规则/设置」三主 tab 且无弹窗时生效；子页返回 = 回上一页，永不直接退桌面

**实现**：
- 每个弹窗内部加 `BackHandler(enabled = show)`：可关闭弹窗调 `onDismiss()`；裁决弹窗空实现（吞掉）
- Compose `BackHandler` 后组合者优先——弹窗开着时 MainScreen 的双击退出自动失效，不加全局状态
- 裁决弹窗同时要堵「点外部关闭」：`onDismissRequest` 不再触发关闭（实现时查 miuix `OverlayDialog` 源码，确认返回键与点外部是否都走 `onDismissRequest`；若是，裁决弹窗传空 lambda）

**盘点范围**（grep `OverlayDialog`/`ConfirmDialog` 全部调用点）：
SmsDetailDialog、ImportRulesDialog、ExportRulesDialog、JsonPreviewDialog、导入冲突 ConfirmDialog（裁决）、AI 页冲突 ConfirmDialog（裁决）、全部已取确认弹窗、地址簿删除确认（如有）。miuix 窗口弹层（WindowSpinnerPreference 下拉）已自带返回处理，不动。

**测试**：UI 测试——弹窗开着按返回：普通弹窗关且页面不跳转；裁决弹窗不关且页面不退出；主 tab 无弹窗双击退出正常。

## 三、Snackbar 合并与文案

- `MainScreen` 收集 `UiNotifier` 时：先 `snackbarHostState.currentSnackbarData?.dismiss()` 再 `showSnackbar(...)`——新消息立即替换，同一时间只有一条，不排队
- 文案（5 秒 + 「我知道了」不变）：
  - 删除规则 → `已删除「xxx」，请首页下拉刷新`
  - 保存规则（新增/编辑统一风格）→ `已保存「xxx」，请首页下拉刷新`

## 四、快递卡片重做

### 4.1 未取件卡布局（三行，无展开态）

```
┌────────────────────────────────┐
│ ● 顺丰速运        14:30     ○  │  ← 品牌点+标题+时间(HH:mm)+圆圈
│ 取件码  A1-2345                │  ← 28sp 等宽 bold（现状字号保持）
│ 📍 绿洲家园3号柜                │
└────────────────────────────────┘
```

- 行1：品牌点(8dp) + 标题 + 时间（`HH:mm`，**卡片不再显示日期**，日期靠吸顶分组头）+ 圆圈（48dp 点击区，视觉不变）
- 行2：取件码大字
- 行3：地址
- 行距收紧：卡片 padding 16dp→14dp，行间 Spacer 12dp/6dp→6dp/4dp
- 删除：expanded 状态、展开区、`DetailRow`、「查看短信」按钮、取件码旁「复制」按钮、`pressFeedbackType`、阴影随 expanded 跳变（常态 2dp 不变）

### 4.2 手势（用户拍板）

| 手势 | 动作 |
|------|------|
| 单击 | 无（无动画无交互无功能，Card 不接 onClick） |
| 长按卡片 | 打开 SmsDetailDialog（弹窗 UI 不变，不加新按钮） |
| 左滑 | 标记已取件（露出动画，见 4.3） |
| 右滑 | 无 |
| 点圆圈 | 切换已取件（不变） |

复制出口全 App 统一：仅 SmsDetailDialog 的「复制全文」。

### 4.3 左滑露出动画

- 结构：卡片下层放一个右对齐主色块（圆角同卡），内书「✓ 已取件」白字；卡片随手势左移露出下层
- 阈值：拖动超过卡片宽度 ~35% 松手 → 生效（标记已取件）+ 卡片动画归位；未过阈值 → 回弹
- 实现：`detectHorizontalDragGestures` + `Animatable` 偏移/回弹（水平手势与 LazyColumn 垂直滚动、PullToRefresh 天然分离；长按与拖动的竞争由 Compose 手势系统仲裁——按下不动=长按，按下即动=拖动，需 UI 测试验证）
- 已取件紧凑卡：不接滑动手势（取消已取用圆圈）

### 4.4 已取件紧凑卡

维持单行紧凑样式（现状）；单击=无；长按=原文弹窗；左/右滑=无；圆圈=取消已取件。

**测试**：Roborazzi 重渲（未取件三行卡 / 已取件紧凑卡 / 左滑中间态如可静态构造）；左滑手势 UI 测试（模拟 drag 过阈值/未过阈值）。

## 六、全局地址簿（地址别名）

**场景**：同一取件地点被多家快递短信提到、叫法不一或过长 → 替换为好记的名字显示。

- **入口**：设置页新增「地址别名」ArrowPreference → 独立页 `AddressAliasScreen`（左上角返回，同主题页范式）
- **页内**：行式列表「包含文本 → 显示为」，可添加、可删除；空态引导文案
- **存储**：SettingsStore（DataStore）存 JSON 列表，键 `address_aliases`；显示层偏好，不开 Room 表，无迁移
- **生效**：显示时替换，不动库存数据——`PackageListViewModel.packages` flow 与别名 flow `combine`，map 出替换后的 address；改别名即时生效，无需重扫
- **匹配**：按列表顺序 `contains`，首个命中生效；无命中显示原地址
- **影响面**：卡片、沉浸模式分组、SmsDetailDialog 的「复制全文」不受影响（复制的是短信原文）；标题计数不受影响

**测试**：别名映射抽纯函数单测（首命中/无命中/空列表/多条顺序）。

## 七、主题配色：砍引擎

**裁决**：删除「固定/动态」引擎切换。配色卡统一为：

- 动态取色开关（开 = 跟随壁纸，API<31 置灰）
- 种子色全网格（关动态时显示；**首项 = miuix 默认**）
- 调色板风格 9 种（不变）
- 色彩规格（置灰逻辑不变）

**实现**（Theme.kt 重构）：
- `seedColor` 可空化：`null`=miuix 默认。存储层用新键或哨兵值（实现时定）；旧 `theme_engine` 键废弃不迁移（升级用户按新结构直接生效：原 FIXED 用户→相当于选了「miuix 默认」；原 MONET 用户→dynamicColor/seedColor 偏好还在）
- controller 三态：
  1. 动态取色开且 API≥31 → `MonetSystem/Light/Dark` + `keyColor=null`（壁纸）
  2. 关动态 + 选了种子色 → `MonetSystem/Light/Dark` + `keyColor=seed`
  3. 关动态 + 选「miuix 默认」→ `System/Light/Dark`（不传 keyColor，miuix 内置板）
- 「miuix 默认」网格首项：miuix `ColorPalette` 是否支持自定义首项待实现时查证；不支持则自绘网格（首项 = miuix 默认蓝色点+「默认」角标）

**测试**：Robolectric 渲染三态主题（默认/种子色/动态）确认 controller 配置正确。

## 十一、沉浸式取件模式

**场景**：站在驿站货架前，一手拎东西一手拿手机——大字、一眼扫到码、按位置聚拢、取完一键清场。

**入口/退出/Tab 状态机**（用户裁决）：
- 入口：长按底栏「快递」tab（隐藏功能，任意 tab 下长按都生效——先切到快递 tab 再进沉浸）
- 沉浸是独立状态，**tab 切换不退出**：沉浸中点「规则」「设置」正常切页，再点「快递」回到的是沉浸视图而非普通列表
- 退出仅三条：长按「快递」/ 系统返回键（沉浸视图在快递 tab 前台时）/ 「全部取完」自动退出
- 实现：MainScreen 级状态 `immersionMode: Boolean`；内容区渲染条件 = `currentTab == PACKAGES && immersionMode`
- 返回键细节：沉浸视图在前台时返回=退出沉浸；沉浸开着但人在规则/设置 tab 时返回=维持现状（双击退出逻辑不变，沉浸状态不动）

**首次进入引导**（用户裁决）：
- 第一次进入弹模态引导：说明这是什么（货架前快速取件视图）、怎么进（长按底栏快递）、怎么退（再长按或返回键）
- 不自动关闭、返回键吞掉、只能点「我知道了」关闭（复用 §2 裁决弹窗的吞返回机制）
- 一次性：DataStore 键 `immersion_guide_shown`，看过不再弹

**行只读**（用户裁决 Q2=B）：行不接任何手势（无左滑、无长按），纯展示；单件管理回普通列表点圆圈

**内容**：
- 数据源：全部未取件记录
- 分组：按**别名替换后**的地址分组；address 为 null 归「其他」组；组按件数倒序；组内按时间倒序
- 分组头吸顶（stickyHeader，同首页日期吸顶套路）
- 空态：「没有待取的快递 🎉」

**行设计**（非纯文本）：
```
10-23   ● 京东              8-2042
10-22   ● 妈妈驿站…         A1-2345
```
- 月日 `MM-dd`：小号、灰色、等宽，对齐成竖线
- 标题列（注意：**不一定是快递品牌名**，可能是驿站名或 fallback「快递」）：8dp 色点 + 定宽省略号
- 取件码：全行最大、等宽粗体、右对齐；**不许截断**——按码长度自适应降档（≤6 位吃满档字号，更长自动降半档），永远完整一行

**底部操作栏**（固定不滚）：
- **A－ / A＋**：字号三档循环（标准/大/特大），行高联动；会话内记忆（rememberSaveable），不落盘
- 智能默认档：打开时待取件 ≤8 → 大档；>8 → 标准档
- **全部取完**：全部待取件标已取 → 自动退出回普通列表（全灰即反馈）；不加确认弹窗（误触代价低，回列表点圆圈可恢复单件）

**测试**：分组/排序逻辑抽纯函数单测；Roborazzi 渲染（多组/空态/特大字号长码）。
